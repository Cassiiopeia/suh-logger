## 테스트케이스: 상위 프로젝트 SLF4J로 로그 출력 위임 전환

| 구분 | 내용 |
|------|------|
| 이슈 번호 | #53 |
| 대상 | suh-logger 로깅 파이프라인 (SuhLogger, AutoConfiguration) |
| 담당자 | @Cassiiopeia |
| 작성일 | 2026-07-04 |

전제: 소비자 스프링부트 웹 앱에 최신 suh-logger 의존성을 `exclude` 없이 추가하고, `logback-spring.xml`에 식별 가능한 커스텀 패턴(예: `>>>[%-5level] %logger{25} ::: %msg<<<`)을 설정한 상태에서 검증한다.

---

### TC-01: 상위 프로젝트 로그 패턴 반영

| 항목 | 내용 |
|------|------|
| 전제조건 | 소비자 앱 `logback-spring.xml`에 커스텀 콘솔 패턴 `>>>[레벨] 로거 ::: 메시지<<<` 설정 |
| 절차 | 앱 구동 → `SuhLogger.info("테스트")` 호출 |
| 기대 | suh-logger 출력이 커스텀 패턴을 그대로 따름 (`>>>[INFO ] k.s.s.util.SuhLogger ::: 테스트<<<`). 기존 JUL ANSI/PID 포맷은 나타나지 않음 |
| 결과 | |

### TC-02: @Slf4j 로그와 동일 파이프라인 공유

| 항목 | 내용 |
|------|------|
| 절차 | 상위 클래스에서 `log.info("상위로그")` (@Slf4j) 와 `SuhLogger.info("suh로그")` 를 같은 실행 흐름에서 호출 |
| 기대 | 두 로그가 동일 패턴·동일 appender로 출력됨. 콘솔/파일 어느 appender로 보내든 두 로그가 함께 기록됨 |
| 결과 | |

### TC-03: 로그 레벨 상위 설정으로 제어

| 항목 | 내용 |
|------|------|
| 전제조건 | `application.yml`에 `logging.level.kr.suhsaechan.suhlogger: WARN` 설정 |
| 절차 | 앱 구동 → `SuhLogger.info("정보")` 와 `SuhLogger.warn("경고")` 호출 |
| 기대 | INFO 로그는 억제되고 WARN 로그만 출력됨 (레벨 필터가 상위 설정대로 적용) |
| 결과 | |

### TC-04: 공개 API 하위호환

| 항목 | 내용 |
|------|------|
| 전제조건 | 이전 버전 suh-logger를 쓰던 상위 프로젝트 코드 (버전만 상향) |
| 절차 | `SuhLogger.info/superLog/lineLog/timeLog/getLogger/infoMsg` 등 기존 호출부를 수정 없이 컴파일·실행 |
| 기대 | 컴파일 에러 없음, 모든 메서드 정상 동작. 코드 수정 불필요 |
| 결과 | |

### TC-05: deprecated 메서드 no-op 동작

| 항목 | 내용 |
|------|------|
| 절차 | `SuhLogger.setLogLevel(SuhLogger.LogLevel.DEBUG)` 및 `SuhLogger.addFileLogger("/tmp/x.log")` 호출 |
| 기대 | 예외 없이 실행. "더 이상 동작하지 않습니다" 안내 WARN 로그만 출력. `/tmp/x.log` 파일은 생성되지 않음 |
| 결과 | |

### TC-06: 플레이스홀더 치환 (timeLog 예외 포함)

| 항목 | 내용 |
|------|------|
| 절차 | `SuhLogger.timeLog(() -> { throw new RuntimeException("실패사유"); })` 호출 → 그리고 정상 케이스 `SuhLogger.timeLog(() -> Thread.sleep(5))` 도 호출 |
| 기대 | 예외 케이스: 메서드명과 예외 메시지("실패사유")가 모두 로그에 표시 (`{1}` 인자 누락 없음). 정상 케이스: 실행 시간이 값으로 정상 치환되어 표시 |
| 결과 | |

### TC-07: exclude 없이 의존성 추가만으로 동작

| 항목 | 내용 |
|------|------|
| 절차 | `implementation 'kr.suhsaechan:suh-logger:x.x.x'` 만 추가 (로깅 exclude 구문 없이) → 빌드·구동 |
| 기대 | 의존성 충돌 없이 정상 빌드·구동. suh-logger 로그와 상위 로그 모두 정상 출력 |
| 결과 | |

### TC-09: 비-웹 애플리케이션 구동 (경계 확인)

| 항목 | 내용 |
|------|------|
| 전제조건 | `spring-boot-starter-web` 없이 순수(non-servlet) 스프링부트 앱에 suh-logger 추가 |
| 절차 | 앱 구동 |
| 기대 | (알려진 제약) SuhLoggingFilter가 servlet API에 의존하므로 웹이 아닌 앱에서는 필터 빈 생성 관련 이슈 발생 가능. 대부분의 상위 프로젝트는 웹 앱이므로 실사용 영향 없음을 확인 |
