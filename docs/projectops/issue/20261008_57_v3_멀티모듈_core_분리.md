📝 현재 문제점
---

- 단일 모듈에 core 로깅, Spring AOP, Servlet 필터가 묶여 있어 WebFlux, non-web(배치·워커), 순수 Java 환경에서 쓸 수 없다.
  - `SuhMethodInvocationLoggingAspect`가 `jakarta.servlet.HttpServletRequest`를 직접 import해 Servlet이 없는 앱에서 클래스 로딩이 깨질 수 있다.
  - `SuhLoggingFilter` 빈이 웹 조건 없이 등록된다.
- 라이브러리 jar 안에 `SuhLoggerApplication`(@SpringBootApplication), `application.properties`, 자동설정의 `@ComponentScan`, Boot 3+에서 읽지 않는 `spring.factories`가 들어 있다.
- 설정이 `@ConfigurationProperties`(Boot 전용)에 묶여 XML·순수 Spring·순수 Java에서 설정할 방법이 없다.
- `CommonUtil`에 직렬화 위험 타입(JTS, Vector, MultipartFile 등) 처리가 하드코딩되어 외부 기여자가 타입을 추가하려면 core를 고쳐야 한다. (관련: #22, #10, #13)

🛠️ 해결 방안 / 제안 기능
---

- 설계 문서: `docs/superpowers/specs/2026-10-08-suh-logger-v3-architecture-design.md`
- Gradle 멀티모듈로 재구성한다: `suh-logger-core`, `suh-logger-spring`, `suh-logger-spring-boot-autoconfigure`, `suh-logger-spring-boot-starter`, 기존 좌표 `suh-logger`(starter 위임), `suh-logger-bom`.
- core는 Spring·Jackson·Servlet 의존 없이 동작하고, 수집 어댑터가 만든 `LogEvent`를 공통 파이프라인(Enricher, Masker, Formatter)이 처리한다.
- 설정을 순수 POJO `SuhLoggerSettings`로 분리하고 Boot 프로퍼티는 이를 바인딩한다.
- 확장 지점(SPI): `TypeHandler`, `MaskingRule`, `LogFormatter`, `ExclusionMatcher`, `JsonCodec`, `RequestContextAccessor`.
- 공개 API 경계: `internal` 패키지 관례, `@Incubating`, `@Deprecated(since, forRemoval)`.
- 2.x 하위호환: 기존 좌표, import 경로, 프로퍼티 키가 그대로 동작한다.
