📝 현재 문제점
---

- Spring Boot 4.x는 Jackson 3(`tools.jackson`)을 쓰는데 라이브러리가 `api 'jackson-databind:2.18.3'`을 강제해 소비자 의존성과 충돌할 소지가 있다.
- WebFlux(리액티브) 앱에서는 요청/응답 로깅을 쓸 수 없다.
- Kotlin 앱에서 함정이 있다.
  - Kotlin 클래스는 기본 `final`이라 `kotlin-spring` 플러그인이 열지 않은 클래스는 프록시가 걸리지 않아 로그가 조용히 누락된다.
  - `suspend` 함수는 실행 시간이 첫 중단 지점 기준으로 잘못 측정되고 `Continuation` 파라미터가 로그에 섞인다.
  - 자체 `ObjectMapper`를 써서 앱의 `jackson-module-kotlin` 설정이 반영되지 않는다.
- Boot 없는 Spring(XML·JavaConfig)은 등록 방법이 없다.

🛠️ 해결 방안 / 제안 기능
---

- 설계 문서: `docs/superpowers/specs/2026-10-08-suh-logger-v3-architecture-design.md`
- 모듈 추가: `suh-logger-servlet`, `suh-logger-webflux`, `suh-logger-json-jackson2`, `suh-logger-json-jackson3`.
- 자동설정이 classpath 조건으로 환경에 맞는 어댑터와 JSON 구현을 고른다. 앱의 `ObjectMapper` 빈을 우선 재사용한다.
- Kotlin: 어노테이션 `@Target`에 `TYPE` 추가, 프록시 불가 대상 기동 시 WARN, `suspend` 함수 처리.
- XML·JavaConfig 등록용 `SuhLoggerConfiguration` 제공.
- 지원 등급: Tier1(Boot 3.x·4.x × Java 17/21 × Servlet·WebFlux·non-web × Java·Kotlin, CI 검증), Tier2(Boot 없는 Spring 6, 순수 Java). javax 레거시는 2차.
